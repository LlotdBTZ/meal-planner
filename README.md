# Meal Planner

Save recipes from TikTok, Instagram, and blog links, pick meals for the week, and copy one
combined grocery list into iPhone Notes. Self-hosted on a Raspberry Pi next to Pi-hole.

1. Share a TikTok/Instagram post (or paste a link or caption) → the recipe name and
   ingredients are pulled out for you, reading the caption, or the spoken audio if needed.
2. Check and fix the ingredients, then save.
3. Tick the meals for this week → get one grocery list, grouped by aisle, with amounts added up.
4. Tap **Copy list** and paste into Notes, where it becomes a checklist.

## Set up on the Raspberry Pi

Needs Raspberry Pi OS Bookworm or later (Python 3.11+). Works on a Pi 3 B+ (1 GB) alongside
Pi-hole: the app uses port **8080** and is capped at 300 MB of RAM.

```bash
git clone https://github.com/LlotdBTZ/meal-planner.git ~/meal-planner
cd ~/meal-planner
sudo deploy/install.sh            # packages, user, venv, systemd units, settings file
sudo nano /etc/meal-planner/.env  # fill in the keys below
sudo deploy/update.sh             # deploy the newest release (vX.Y.Z tag on main)
```

Open `http://<pi-address>:8080` and log in with `APP_PASSWORD`.

- **Firewall:** if the Pi runs one (nftables, ufw), allow TCP 8080 from your LAN only,
  the same as Pi-hole's admin page. Don't forward the port on your router.
- **Memory cap:** if `install.sh` warns that the memory controller is off, follow its
  one-line fix and reboot; until then the 300 MB cap isn't enforced. Tip: in Pi-hole's
**Local DNS → DNS Records**, point a name like `meals.lan` at the Pi so you don't need the IP.

### Settings (`/etc/meal-planner/.env`)

| Key | What it is | Where to get it |
| --- | --- | --- |
| `APP_PASSWORD` | The one password for logging in | Make one up |
| `SESSION_SECRET` | Signs the login cookie | Generated by `install.sh`. Changing it logs everyone out |
| `ANTHROPIC_API_KEY` | Reads recipes from captions/transcripts | [console.anthropic.com](https://console.anthropic.com/) → API Keys |
| `CLAUDE_MODEL` | Claude model to use | Default `claude-opus-5-5`; `claude-haiku-5-5` is much cheaper if results stay good |
| `TRANSCRIBE_API_KEY` | Speech-to-text, only for recipes that are spoken, not written | [platform.openai.com/api-keys](https://platform.openai.com/api-keys) |
| `TRANSCRIBE_MODEL` | Speech-to-text model | Default `whisper-1` |
| `YTDLP_COOKIES` | Optional cookies file for Instagram ([below](#instagram-cookies)) | — |
| `PORT` | Port to listen on | Default `8080` |

`DATA_DIR` is ignored on the Pi; the service always uses `/var/lib/meal-planner`.
After editing settings: `sudo systemctl restart meal-planner`.

### Updates deploy themselves

Every 15 minutes the Pi checks GitHub for a new release tag (`vX.Y.Z` on `main`) and deploys
it with `update.sh`: back up the database, install, restart, check `/health`. If the new
release isn't healthy, the previous one is put back and that tag isn't tried again
automatically. GitHub can't reach the Pi; the Pi only pulls.

```bash
journalctl -u meal-planner-autodeploy -n 20     # what the last check did
sudo systemctl disable --now meal-planner-autodeploy.timer   # turn auto-deploy off
```

Keep the clone `install.sh` was run from (e.g. `~/meal-planner`): the timer fetches tags into
it. To deploy or roll back by hand:

```bash
cd ~/meal-planner && git fetch --tags origin
sudo deploy/update.sh          # newest vX.Y.Z tag on main
sudo deploy/update.sh v0.1.0   # a specific tag, which is also how you roll back
```

Rolling back by hand puts the newer tags on a skip list (`/opt/meal-planner/skipped-tags`) so
auto-deploy doesn't undo it; deploying a tag by hand takes it off the list. Releases that fail
their health check land on the same list.

### Where things live

| | |
| --- | --- |
| Code | `/opt/meal-planner/current` (→ `releases/<tag>`, last 3 kept) |
| Data (database, thumbnails, backups) | `/var/lib/meal-planner` |
| Settings | `/etc/meal-planner/.env` |
| Logs | `journalctl -u meal-planner -f` |
| Status / memory use | `systemctl status meal-planner` |

yt-dlp updates itself weekly (`meal-planner-ytdlp-update.timer`) because TikTok and
Instagram change often; this restarts the app. Run it now with
`sudo systemctl start meal-planner-ytdlp-update`.

## On the iPhone

### Add to Home Screen

In Safari, open the app, log in, tap **Share → Add to Home Screen**. It opens full-screen with
its own icon. The Home Screen app keeps its own login, separate from Safari, so you log in
once in each.

### Share from TikTok/Instagram (iOS Shortcut)

Websites can't appear in the share sheet, so a Shortcut passes the link to the app:

1. Open **Shortcuts** → **+** → name it **Add to Meal Planner**.
2. Tap the **ⓘ** (details) → turn on **Show in Share Sheet**. Set it to receive **URLs** and
   **Text**, and if there's no input: **Stop and Respond**.
3. Add **URL Encode** → input: *Shortcut Input*.
4. Add **Text** → `http://meals.lan:8080/add?url=` followed by the *URL Encoded Text* variable
   (use your Pi's name or IP; with Tailscale, your `https://….ts.net` address instead).
5. Add **Open URLs** → input: the *Text* from step 4.

In TikTok or Instagram tap **Share → Add to Meal Planner** (it may be under **More**). Safari
opens the Add page and starts getting the recipe right away. The first time, log in in Safari.

### Copying the list

**Copy list** puts the list on the clipboard; paste into a new note in Notes and tap
**Checklist**. Over plain LAN HTTP, iOS sometimes blocks automatic copying. If it does, the
app shows the list in a text box so you can select and copy it yourself. With Tailscale
HTTPS, copying always works.

## Instagram cookies

Instagram sometimes refuses posts unless you're logged in ("Paste the caption instead, or set
up Instagram cookies"). Pasting the caption always works. To fetch these posts directly:

1. Log in to Instagram in a desktop browser. A spare account is safer: Instagram may flag
   accounts used by downloaders.
2. Export cookies in Netscape `cookies.txt` format with a "cookies.txt" browser extension.
3. Copy it to the Pi and make it readable and writable only by the app (yt-dlp refreshes it):
   ```bash
   sudo install -o mealplanner -g mealplanner -m 600 cookies.txt /var/lib/meal-planner/cookies.txt
   ```
4. Set `YTDLP_COOKIES=/var/lib/meal-planner/cookies.txt` in `/etc/meal-planner/.env` and
   restart. Delete your local copy; it is as good as your password. Never commit it.

Cookies expire after a while; repeat when Instagram starts refusing again.

## Optional: remote access and HTTPS with Tailscale

By default the app is reachable only on your home network. With
[Tailscale](https://tailscale.com/) you can use it from anywhere, over HTTPS:

1. Install Tailscale on the Pi (`curl -fsSL https://tailscale.com/install.sh | sh`,
   then `sudo tailscale up`) and the Tailscale app on the iPhone, using the same account.
2. In the Tailscale admin console → **DNS**, enable **MagicDNS** and **HTTPS Certificates**.
3. On the Pi: `sudo tailscale serve --bg 8080`. The app is now at
   `https://<pi-name>.<tailnet>.ts.net` for devices on your tailnet only (not the public internet).
4. Use that address for the Home Screen app and the Shortcut.

## Backups and restore

The database is backed up nightly to `/var/lib/meal-planner/backups/meal-planner-YYYY-MM-DD.db`;
the newest 14 are kept, and `update.sh` makes one before every deploy. Back up now:

```bash
sudo deploy/backup.sh
```

Copy backups off the Pi now and then (for example `scp` them to your computer); an SD card
failure takes the backups with it. To restore:

```bash
sudo systemctl stop meal-planner
sudo -u mealplanner cp /var/lib/meal-planner/backups/meal-planner-YYYY-MM-DD.db \
    /var/lib/meal-planner/meal-planner.db
sudo rm -f /var/lib/meal-planner/meal-planner.db-wal /var/lib/meal-planner/meal-planner.db-shm
sudo systemctl start meal-planner
```

Recipe thumbnails live in `/var/lib/meal-planner/thumbnails` and aren't in the database
backups. If they're lost, recipes still work but show no picture.

## Development

```bash
python3 -m venv .venv
.venv/bin/pip install --require-hashes -r requirements-dev.txt   # locked deps + dev tools
.venv/bin/pip install --no-deps --no-build-isolation -e .        # the app itself
.venv/bin/pip install yt-dlp                                     # unlocked on purpose
ln -sf ../../scripts/git-hooks/pre-commit .git/hooks/pre-commit  # pre-commit hook
cp .env.example .env               # set APP_PASSWORD and SESSION_SECRET at least
.venv/bin/python -m app.main       # http://localhost:8080
.venv/bin/pytest -q                # tests never touch the network or need API keys
.venv/bin/ruff check . && .venv/bin/ruff format --check .
```

The pre-commit hook blocks commits that contain a secret ([gitleaks](https://github.com/gitleaks/gitleaks),
which must be installed on `PATH` or in `~/.local/bin`) and runs ruff on staged Python files.
CI runs the same checks, but a secret caught there has already been pushed to a public repo.

### Releasing

1. In a PR: bump `version` in `pyproject.toml` and add a `## [X.Y.Z]` section to
   `CHANGELOG.md`.
2. After it merges: `git switch main && git pull && git tag -a vX.Y.Z -m vX.Y.Z && git push origin vX.Y.Z`.
3. CI publishes a GitHub Release from the CHANGELOG, and the Pi deploys the tag within ~15
   minutes.

This repo is public: never commit secrets. CI scans every change with gitleaks, audits the locked
dependencies with pip-audit, and GitHub blocks pushes containing known key formats. How we work (branches, commits, PRs, releases)
is in [CLAUDE.md](CLAUDE.md). GitHub
repository settings are managed with Terraform in [infra/github/](infra/github/).
